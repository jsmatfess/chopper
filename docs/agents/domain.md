# Domain docs

Use a single-context layout: root GLOSSARY.md and docs/adr/.

Before exploring, read GLOSSARY.md when present and ADRs relevant
to the area being changed. If absent, proceed silently.
The domain-modeling skill creates these documents lazily when
terms or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses and tests.
If a needed concept is missing, reconsider the terminology or
note the gap for domain-modeling.

Surface conflicts with existing ADRs explicitly, including the
decision and reason for reconsidering it.

Continue using the owning specifications and documentation routed
by AGENTS.md; these domain docs supplement those sources.
