## Browser completion marker termination and committed export preservation (2026-10-21)

The next open interruption boundary was marker finalization. The maintained
[`test-browser-termination.mjs`](../../../scripts/test-browser-termination.mjs) now
reports contract v2 and adds cancellation and tab close after a real marker write
before close, and after marker close before the worker's success reply. Its
previous six cases remain. All ten cases use the production client, default WASI
engine and storage worker, with route-only pause hooks in a fresh temporary
Chromium context and a same-origin OPFS destination. No new engine injection API,
storage algorithm, policy selector or default is introduced.

The write-before-close cases retain a zero-byte `CHOPPER-COMPLETE.json` entry on
this build. It is not a valid record and does not certify completion, despite the
filename existing. The close-before-reply cases expose a valid 67-byte v1 record
while the public client still reports `running`. They verify all five CSVs against
the 17-row source before termination, then compare every CSV, manifest and marker
hash after cancellation/tab cleanup and same-client retry. Those committed folders
remain complete and unchanged; cancelling the pending reply does not roll them
back. In both cases the workspace and lock follow the existing cancellation or
abandoned-workspace cleanup paths. Each of the five cancellation cases completes
a new exact job through the same client, and all unrelated entries survive.

Earlier high-level UI/documentation wording said folders merely containing the
marker were complete, while the detailed browser contract already rejected an
empty entry. The tests confirm that distinction. Failure, confirmation and
cancellation guidance now explicitly require a valid JSON completion record;
the normal browser runner parses and checks the record's complete/engine/version
fields and physical result-file count instead of testing its name alone. The
marker format and write/close ordering are unchanged. A cancellation status can
therefore coexist with a completed destination if marker commit preceded reply.
