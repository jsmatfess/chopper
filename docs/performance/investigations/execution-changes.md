## Execution changes

1. **Balanced ranges.** Intermediate balanced splits share the preceding immutable row file. A scan locates byte boundaries and writes a new group catalog, without copying row payloads. When a shuffle feeds a balanced split, boundaries are produced while consuming the shuffle instead.
2. **Encoded output plans.** The final operation serializes directly into a retained CSV byte stream and a disk-backed chunk catalog. Exact byte/row limits, BOMs, headers, and empty allocation outputs are decided here. Execution copies these ranges into output files or compressors; it does not deserialize and serialize the rows again. Intermediate row files are released before confirmation.
3. **Multiway merging.** Small sorts stay in memory. External sorts merge up to 64 runs at a time, constrained by observed row memory and read buffers. Run catalogs remain bounded through hierarchical compaction. The final merge is an iterator consumed directly by the next stage. Random-key collisions retain the original domain-specific refinement.
4. **Parallel compression.** Native gzip, Zstandard, and ZIP member compression use the existing worker pool in bounded batches. Each task reads an independent range from the encoded snapshot. Memory reservations include codec state and group metadata; ZIP batch selection also considers available temporary space. Results enter the manifest and ZIP in logical order. Plain output and ZIP assembly remain sequential. Errors and cancellation still discard the job-owned staging directory before publication.
5. **Operation fusion.** Initial partitioning and uniform shuffling receive rows directly from the parser. Plain row/byte splitting encodes directly during ingestion. Partition → uniform shuffle uses a combined partition/random sort key. Assignment → uniform shuffle retains the original quota draws and stratification traversal, then sorts by allocation/random key instead of restoring an intermediate allocation order. Uniform shuffle → balanced split consumes sorted rows directly. Adjacent uniform shuffles may discard earlier permutations, retaining original operation indices for random domains and stage reporting. A bounded partition-domain cache avoids repeatedly constructing the same group seed.

`auto` currently selects uniform shuffling and uses the same optimizations. Buffer shuffles retain their original behavior. A shuffle before assignment or balanced splitting cannot generally be deleted, because it can change membership. Fusion never reorders logical steps or renumbers their random domains. Some composed pipelines still need intermediate datasets, especially where subsequent operations require exact group counts.

The browser uses the same ingestion, range, fusion, and merge code. WASI sorting and output compression remain sequential. These changes do not introduce browser threading or a new storage bridge.
