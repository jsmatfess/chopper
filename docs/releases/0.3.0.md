# Chopper 0.3.0

Chopper 0.3 adds automatic execution settings, an independent Analyze action, and a clearer view of what a Run is doing. Release package hashes and platform validation belong to the candidate's artifact and validation receipts.

## Auto and Analyze

- Run validates and processes the selected input directly. Analyze is optional. When its observations still match the input and parser settings, Run can use them to refine its plan. Native Windows uses fresh observations from Run because saved Analyze advice cannot yet be reliably matched to the input there.
- Auto uses input size, pipeline shape, available preview information, and runtime limits to choose resources and eligible execution strategies. The hosted editor shows the automatic settings and lets you switch to Advanced for explicit controls. Results explain the plan that actually ran.
- Exact assignments, group membership, pipeline ordering, requested shuffle distributions, and strict serialized CSV caps remain part of the [processing contract](../specification.md). Working-memory budgets account for engine working allocations. Browser and process memory can be higher.

## Hosted workbench

- Configure and Execution have separate views with a linked Output Plan. The execution graph supports a zoom slider, width fitting, page scrolling, and stacked cards for repeated steps. The timeline records observed pauses and shows destination saving separately from completion-marker verification.
- Group percentage errors appear immediately below the inputs. Results show processing time, warnings, and execution details.
- Plain, gzip, and Zstandard results can write into the selected destination as processing runs. ZIP uses staged export. A valid `CHOPPER-COMPLETE.json` marks a completed browser export. See [browser requirements and storage behavior](../browser.md).

## Selected performance measurements

These are matched complete-job comparisons from the linked development experiments. The baseline is the control in each experiment. Results apply to the recorded fixtures and hosts.

- Two simultaneous 2 GiB plain Partition jobs, each with 1,152 files, completed in a median 19.14 s versus 34.20 s under Linux on WSL and 18.41 s versus 22.45 s on native Windows with bounded publication. The 192-file control missed the adoption gate. [Bounded publication and browser I/O measurements](../performance/investigations/bounded-io-overlap-adoption-2026-11-22.md)
- On the tested native counted Partition → Balanced workload, median complete Run fell from 11.82 s to 6.81 s under Linux on WSL and from 12.58 s to 7.72 s on native Windows. [Native Auto qualification and controls](../performance/investigations/automatic-native-execution-bounds-2026-11-22.md)
- On the measured plain hosted jobs, default bounded I/O overlap saved 7.02–16.10 s in limits-only streaming jobs. A single plain Partition saved 1.06–4.12 s using source read-ahead. [Browser I/O measurements](../performance/investigations/bounded-io-overlap-adoption-2026-11-22.md)

## Packages and compatibility

The native packages contain the x86-64 Windows or Linux CLI. The Linux binary requires glibc 2.34 or later. The hosted bundle is separate and requires supported desktop Chrome or Edge. Check the [CLI Run reference](../run-cli.md) and [hosted requirements](../browser.md) for configuration and runtime details.
